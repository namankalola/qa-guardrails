AriseQA Guardrails

One policy and one pipeline for every Playwright + TypeScript repository. It covers code quality, framework architecture, test reliability, security and dependencies, and pull-request controls. Teams tune thresholds within fixed bounds. A small set of hard floors cannot be switched off by anyone.

What is enforced

The five guardrails

Each control is marked as a floor (always blocks, not configurable), bounded (team sets the value within limits) or opt-in.

1

Code quality

Every repo shares the same type-checked lint baseline and strict compiler settings. Lint runs twice: once with the repo's config, then again with an enterprise floor config that ignores eslint-disable comments.

  • Zero TypeScript errors (tsc --noEmit)floor
  • Zero ESLint errors; floored rules enforced with inline disables ignoredfloor
  • Lint warnings allowed (0–50), cyclomatic complexity (10–25), unsafe-any strictnessbounded
  • Prettier check, Conventional Commit PR titlesbounded

ESLint 10 flat config, typescript-eslint, Prettier, commitlint, husky + lint-staged

2

Automation framework

The Page Object rules that used to live only in review checklists and CLAUDE.md are now lint errors, enforced by the custom ariseqa-qa ESLint plugin.

  • Specs never use the raw page fixture or build locatorsbounded
  • Specs import test/expect from app fixtures onlybounded
  • Locators are private readonly; interactions go through WebActionsbounded
  • Apps never import from sibling appsbounded

@ariseqa/eslint-config → ariseqa plugin (5 rules, unit-tested with ESLint RuleTester)

3

Automated test quality

Retrying until green and skipping indefinitely are both blocked. Flaky tests are quarantined against an owner ticket with an expiry date, and the flake rate has a budget.

  • No test.only, no hard waits (waitForTimeout, networkidle), assertions requiredbounded
  • Every test carries an approved tag (drives --grep suites)bounded
  • Retries capped at policy (0–2), whatever the config file saysbounded
  • Quarantine needs a ticket and an expiry ≤ 60 days; ≤ 10 % of the suitebounded
  • Flake rate (passed only on retry) within budget (0–10 %)bounded

@ariseqa/playwright-guardrails withGuardrails(), quarantine and flake gates over Playwright JSON reports

4

Security and dependencies

Secrets and critical advisories always block. Other thresholds are set by the team, and every exception expires.

  • No secrets in commits (gitleaks with enterprise rules, incl. Jira/Atlassian tokens)floor
  • No critical advisories in dependencies or runner images, and they can't be ignoredfloor
  • High/moderate threshold; ignores need a reason and expire within 90 daysbounded
  • Licence allow list owned by Legal; copyleft cannot be addedfloor
  • Semgrep enterprise rules (TLS off, hard-coded auth, shell injection, secret logging)bounded
  • CodeQL, ZAP baseline (authorised hosts only), Hadolint + Trivy on imagesopt-in

gitleaks, Semgrep CE, npm/pnpm audit, OSV-Scanner, Trivy (CycloneDX SBOM), OWASP ZAP, Hadolint

5

CI/CD and pull requests

A 20-line caller in each repo runs the central pipeline, pinned by commit SHA. Branch rules are version-controlled and require one check.

  • 1 approval + CODEOWNER review, last-push approval, stale reviews dismissedfloor
  • Signed commits, linear history, no force-push or deletion on mainfloor
  • Third-party actions pinned to commit SHAs (warn → block)bounded
  • Org-level required workflow as a backstop if a caller is deletedopt-in
  • Dependabot, OpenSSF Scorecard, cosign signing + build provenanceopt-in

Reusable workflow_call, rulesets as code (governance/rulesets), CODEOWNERS, PR template

How a pull request is gated

Seven jobs, one required check

The policy job resolves the team file against the enterprise defaults and fails on any out-of-bounds value or floor override. Every other job reads its thresholds from that output. The gate fails if a floor job doesn't succeed or any gate fails.

Governance model

Floors are fixed, everything else is bounded

Hard floors

These are literals in the policy schema. Setting one in a team file, even to its default value, fails the policy job with a pointer to the exception process.

  • Zero type errors and zero lint errors
  • Secret scanning on every PR
  • Critical advisories block and are never ignorable
  • Licence allow list (Legal-owned)
  • Review rules: owner approval, no self-approval, signed history

Bounded team settings

These live in guardrails.config.yml with CODEOWNERS review. The schema is strict, so a typo fails loudly instead of silently disabling a gate.

For teams

Onboarding a repository

It takes about 30 minutes: copy templates/consumer/, set the test command and team name, install three packages, wrap the Playwright config, then run eslint --fix and fix what's left. 

# .github/workflows/guardrails.yml
jobs:
  guardrails:
    uses: ariseqa/qa-guardrails/.github/workflows/guardrails.yml@<sha>
    with:
      guardrails-ref: v1
      test-command: npm run test:smoke
    secrets:
      test-env: ${{ secrets.TEST_ENV }}
# guardrails.config.yml - only what differs
version: 1
team: qa-automation
testQuality:
  maxRetries: 1
  flakeRateBudgetPct: 2
security:
  vulnerabilities:
    failOn: high

Parking a flaky test

Use quarantine('SCRUM-12', '2026-11-30', 'race on cart badge') in the test's details. The test leaves PR runs and runs nightly instead. When the expiry passes, the PR fails until someone fixes the test or deletes it.

Rollout

From pilot to org-wide enforcement

  1. Platform setup

    ~1 day

    Push the repo, set up the protected release environment, tag v1.0.0 to publish the @ariseqa/* packages.

  2. Pilot, warn mode

    2 weeks · 1–2 repos

    Gate runs but isn't required yet. Measure pass rate, duration and false positives, then tune the defaults.

  3. Enforce by wave

    4–6 weeks · 5–10 repos per wave

    Require guardrails / gate. Legacy repos start with bounded leniency and a dated plan to tighten.

  4. Org backstop

    after wave 2

    Activate the required-workflow ruleset for guardrails=enforced repos and move action pinning from warn to block.
